# نظام توثيق الأداء - جمعية فرقان لتحفيظ القرآن الكريم

## المرحلة 1 (منجزة): الأساس

- هيكل المجلدات الكامل
- صفحة الدخول (login.html) مرتبطة بـ Firebase Authentication
- إعادة التوجيه التلقائي من index.html حسب حالة الجلسة
- لوحة التحكم الرئيسية (dashboard.html) بالبطاقات الخمس عشرة كاملة
- شريط علوي مشترك (اسم المستخدمة، الدور، زر الخروج)
- تعريف الأدوار الخمسة والصلاحيات (js/firebase/roles.js)
- 15 صفحة أقسام كصفحات مؤقتة (placeholder) تعمل وتتنقل بشكل صحيح، وستُستكمل بالحقول الكاملة في المرحلة القادمة

## قبل التشغيل: يلزم فتح مشروع Firebase

1. أنشئي مشروعًا في https://console.firebase.google.com
2. فعّلي: Authentication (Email/Password) + Cloud Firestore + Storage
3. من Project Settings انسخي بيانات الإعداد (firebaseConfig) وضعيها في:
   `js/firebase/config.js`
4. أنشئي يدويًا (أو عبر Console) حسابات المستخدمات في Authentication، ثم لكل مستخدمة أضيفي مستند مطابق في Firestore:
   - Collection: `users`
   - Document ID: نفس الـ UID الخاص بالمستخدمة في Authentication
   - الحقول: `{ name: "الاسم", email: "البريد", role: "employee" }`
   - القيم المتاحة لـ role: `employee` / `unit_officer` / `unit_manager` / `dept_manager` / `education_admin`

```
│   ├── components/
│   │   ├── topbar.js        الشريط العلوي المشترك
│   │   └── sections-config.js  تعريف موحّد لكل الأقسام الـ15

```

## كيفية التشغيل محليًا

لا يمكن فتح index.html مباشرة بنقرتين بسبب استخدام ES Modules؛ يلزم خادم محلي بسيط:

```bash
cd furqan-reports
python3 -m http.server 8080
```

ثم افتحي: http://localhost:8080

## المرحلة 2 (منجزة): البيانات الأساسية + الأهداف والمستهدفات

- `js/report-state.js`: إدارة مسودة التقرير في Firestore (إنشاء/تحميل/حفظ لكل قسم)
- `js/components/form-helpers.js`: أدوات مشتركة (عداد أحرف، حقول شرطية، حساب حالة المؤشر، إشعار حفظ)
- `js/components/org-data.js`: البيانات التنظيمية (الأقسام، الوحدات، المكاتب، الأهداف) — **عدّليها بالقيم الفعلية للجمعية**
- `pages/basic-data.html`: نموذج كامل (الجهة، الفترة بأنواعها السبعة مع حقول شرطية للشهر/الفصل، بيانات معدة التقرير)
- `pages/goals.html`: نموذج كامل (الهدف الاستراتيجي، الأهداف التشغيلية متعددة الاختيار، مستوى ونسبة التحقق مع عداد مرئي، تفسير بحد 300 حرف، أدلة التحقق مع خيار "أخرى")

كل نموذج يُنشئ أو يستكمل "مسودة تقرير" واحدة نشطة للمستخدمة، ويُحفظ تلقائيًا في مجموعة `reports` على Firestore عند الضغط على "حفظ البيانات".

## المرحلة 3 - جزء 1 (منجزة): مؤشرات الأداء + الأعمال والبرامج

- `js/components/repeatable-list.js`: محرك عام لأي قسم "قابل للتكرار" (زر + إضافة/حذف) بدون فقدان تركيز الكتابة عند التعديل
- `pages/indicators.html`: عدد غير محدود من المؤشرات، مع **حساب الحالة تلقائيًا** (🟢🟡🟠🔴⚪) من المستهدف والمتحقق واتجاه المؤشر، وظهور حقول الانحراف السبعة تلقائيًا فقط عند التعثر
- `pages/programs.html`: عدد غير محدود من الأعمال، مع نوع العمل (16 خيارًا وحقل "أخرى")، وحساب **نسبة الإنجاز ونسبة الحضور تلقائيًا** من الأعداد المدخلة

## المرحلة 3 - جزء 2 (منجزة): أدوات القياس + نقاط القوة + الصعوبات + فرص التحسين

- `pages/measurement-tools.html`: نسبة الاستجابة تُحسب تلقائيًا (المستجيبات ÷ حجم العينة)
- `pages/strengths.html`: محدودة بـ5 نقاط كحد أقصى، مع عداد مرئي وتعطيل زر الإضافة عند الوصول للحد
- `pages/difficulties.html`: حقول "الدعم المطلوب" الثلاثة تظهر تلقائيًا فقط عند اختيار أن الصعوبة "ما زالت قائمة"
- `pages/improvement-opportunities.html`: شارة أولوية ملوّنة (عاجلة/عالية/متوسطة/منخفضة) تتحدث لحظيًا

## المرحلة 3 - جزء 3 (منجزة): المبادرات + قصص النجاح + التوصيات + خطة الفترة القادمة + الشواهد

- `pages/initiatives.html`: حقل "متطلبات التعميم" يظهر تلقائيًا عند اختيار أن المبادرة قابلة للتعميم
- `pages/impact-stories.html`: تنبيه خصوصية دائم أعلى الصفحة، وحقل رابط الشاهد يظهر تلقائيًا عند تفعيل "تم التوثيق"
- `pages/recommendations.html`: شارة أولوية ملوّنة لكل توصية
- `pages/next-period-plan.html`: محصورة بين 3 و5 أعمال، تبدأ بـ3 عناصر فارغة تلقائيًا، وتمنع الحفظ إن قل العدد عن 3
- `pages/evidence.html`: رفع ملفات حقيقي إلى Firebase Storage (مع شريط حالة الرفع) أو رابط خارجي بديل، مع ربط كل شاهد بأحد الأقسام الـ15 ودرجة السرية

**بهذا تكتمل المرحلة 3 بالكامل: جميع الأقسام الـ15 مبنية بحقولها الكاملة والحقول الشرطية.**

## المرحلة 4 (منجزة): تحليل النتائج + لوحة المؤشرات الإحصائية
- `pages/results-analysis.html`: إحصاءات محسوبة تلقائيًا (عدد المؤشرات، البرامج، متوسط الإنجاز...) + رسمان بيانيان (Chart.js): توزيع حالة المؤشرات ونسبة إنجاز البرامج + حقول تحليل نصية

## المرحلة 5 (منجزة): مسار الاعتماد الكامل
- `js/firebase/workflow.js`: منطق الحالة الكاملة (مسودة → مُرسل → معتمدة الوحدة → معتمدة القسم → معتمد نهائيًا)، مع دعم الرفض والإعادة للتعديل وسجل تاريخي كامل
- `pages/review-approval.html`: قائمة تحقق من اكتمال الأقسام + زر إرسال للاعتماد + شريط حالة + سجل المراجعة
- `pages/unit-review.html` / `pages/department-review.html` / `pages/admin-dashboard.html`: لوحات مخصصة لكل دور تعرض التقارير بانتظار اعتمادها مع أزرار اعتماد/إعادة/رفض + ملاحظات؛ لوحة إدارة التعليم تعرض أيضًا إحصائية عامة لكل التقارير حسب الحالة

## المرحلة 6 (منجزة): التحليل الذكي
- `pages/ai-analysis.html`: يجمّع بيانات التقرير الحالي (مؤشرات، برامج، صعوبات...) ويرسلها لواجهة Anthropic API لتوليد: ملخص تنفيذي، أهم المنجزات، أهم الصعوبات، نقاط القوة، فرص التحسين، التوصيات، أولويات الفترة القادمة
- `js/ai-config.js`: مكان وضع مفتاح API (يحتاج تعبئة يدوية، راجعي التنبيه الأمني داخل الملف)

## المرحلة 7 (منجزة): تقرير PDF
- `reports/print-report.html`: يجمّع كل أقسام التقرير (بيانات أساسية، مؤشرات بجدول وحالة ملوّنة، رسم بياني، برامج، نقاط قوة، صعوبات، توصيات، شواهد) بتنسيق طباعة احترافي، مع زر "طباعة / حفظ PDF" يستخدم خاصية الطباعة المدمجة بالمتصفح (Ctrl+P → Save as PDF)

**🎉 بهذا اكتملت كل المراحل السبع المطلوبة في المواصفات الأصلية.**
